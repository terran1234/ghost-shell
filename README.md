# 과제 2 — 내가 설계한 미니게임: Ghost Shell

브라우저에서 실행되는 CLI 스타일 해킹 타자 게임입니다. 로그인 없이 아래 링크로 바로 플레이할 수 있습니다.

## 결과물 주소
https://claude.ai/artifact/3gsRptaJpfH7pDeWyFxiUe

## 소스
이 저장소의 `ghost-shell.html` (단일 파일, HTML/CSS/JS)

## 짧은 확인 방법
- 위치: 결과물 링크 접속 → 미션 브리핑 화면
- 행동(3단계 이내): ① Space 또는 클릭으로 임무 시작 → ② 화면에 뜨는 문자열을 키보드로 입력 → ③ 30초 제한시간 내 3단계(정찰→침입→흔적삭제)를 모두 클리어
- 통과 모습: "ACCESS GRANTED" 화면과 함께 보수 지급 연출이 뜬다
- 실패 모습: 제한시간 초과 또는 탐지율 100% 도달 시 "TRACED" 화면이 뜨고, Space/클릭으로 즉시 재시작된다

## AI와 나의 판단
- AI에게 맡긴 일: 게임 로직 구현(충돌·타이핑 판정, 난이도 곡선), UI/CSS, 저장·복구 코드, 버그 원인 조사(z-index, 포커스, IME, 캐시)
- 직접 판단한 일: 장르·소재 선정(실제 침투 방법론 단계 순서 차용), 난이도 값 하나만 비교하는 실험 설계, UI 톤(미니멀 CLI, 메신저 연출) 방향 결정
- AI 제안을 따르지 않은 일: 초기 네온/배경 이미지 연출을 실제 CLI 느낌에 맞지 않는다고 판단해 순정 검정 배경으로 되돌림

## 과제 체크리스트별 기록
- 카드 1 - 30초 핵심 규칙: 확인 완료
- 카드 2 - PC 경계 검사: 확인 완료 (일시정지 기능 포함)
- 카드 3 - 10회 전후 난이도 비교: 아래 표 참고

### 카드 1 — 30초 핵심 규칙 확인 기록

한 판의 시작·진행·종료·재시작을 실제로 실행한 기록:
- 시작: 결과물 링크를 새 시크릿 창에서 로그인 없이 열면 미션 브리핑 화면이 뜬다. Space 또는 화면 클릭 시 타이머가 30.0s부터 카운트다운을 시작한다. (C01, C07)
- 진행: 화면 상단에 현재 레이어(LAYER 01 · RECON & SCAN), 남은 시간(T-XX.Xs), 탐지율(DET 바)이 계속 보인다(C03, C05). 떨어지는 단어의 글자를 하나 입력할 때마다 그 글자가 즉시 "입력됨" 표시로 바뀐다 — 핵심 조작 1회가 상태 변화 1회로 반영된다(C04, C06).
- 종료: 3레이어를 모두 클리어하면 30초 이전이라도 "ACCESS GRANTED" 화면이 뜬다(성공). 시간이 0이 되거나 탐지율이 100%에 도달하면 "TRACED" 화면이 뜬다(실패). 두 경우 모두 시작 후 30초 이내에 도달한다(C07).
- 재시작: 결과 화면에서 Space/클릭 → 브리핑 화면 → 다시 Space/클릭하면 타이머 30.0s·탐지율 0%·클리어 수 0으로 완전히 초기화된 새 판이 시작된다. 성공으로 끝났든 실패로 끝났든 동일하게 초기화된다(C08, C09).

### 카드 3 — 난이도 값 비교 (10회 전/후, 총 20회)

바꾼 값: `DIFF.normal.baseSpeed` 하나만 변경 (나머지 상수는 고정)
- 변경 전: `baseSpeed = 38`
- 변경 후: `baseSpeed = 34` (현재 적용값)

**최종 선택: baseSpeed = 34**

클리어 단어 수의 중앙값은 두 조건에서 동일(11개)했지만, 놓친 단어(breach) 수가 38에서는 평균 2.0회·최대 4회인 반면 34에서는 평균 1.1회·최대 2회로 절반 가까이 줄었다. 클리어 수 범위도 38은 7~13(폭 6)으로 편차가 컸고 34는 9~13(폭 4)로 더 안정적이었다. 평균적인 진행 속도는 비슷하게 유지하면서 놓치는 빈도와 편차를 줄이는 34를 최종값으로 선택했다. (방법론 상세는 [difficulty-test.md](./difficulty-test.md) 참고)
